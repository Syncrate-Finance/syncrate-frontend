Existing SGLD icon assets are unchanged, and the Robinhood form uses the same /SGLD-icon.png image as Base. Actual network names remain on balances, transactions and supported opportunities. No replacement Robinhood promotional badge was added. Legacy wallet controls retain their Base-only default; only the shared overview header accepts both supported networks. The new Robinhood form explicitly requires4663. ## Robinhood transaction behavior

- Engine/token proxy: `0x8D1C9e4B54E143F56Bbd33F861Bc0fB9fb301AE9`. Implementation: `0x64789096edf7a3F64A92aD705e64A06e4CC32888`. Never use retired 6155 gateway or the implementation as token/spender.
- Base controller: `0xddD8d43C21aa8A5Ec60cF92c30b72a3CF4D8C08b`. Managed gold oracle: `0xDbb6D70553c388Eba28860b6d0C7406B840063f3`.
- USDG: `0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168`. USDG/USD feed: `0x61B7e5650328764B076A108EFF5fa7282a1B9aD2`. All addresses are0x-prefixed in configuration.
- Reads verify chain IDs, fresh chain timestamps, proxy implementation slot and reviewed implementation/controller bytecode hashes. Unexpected upgrades fail closed until reviewed. USDG/feed identities are checked. Price reads use the deployed contracts' validated feed accessors; no peg or stale-price fallback.
- Integer quotes match the contracts: USDG 6 decimals, SGLD 18 decimals, USD prices 18 decimals. Redemption deducts the current fee; cap checks use canonical total supply and current adjustable cap. Minimum receive is protected at 0.5% slippage; nonzero quotes never set a zero minimum. Confirmation refreshes and re-reviews changed quotes. Requests use a 14-minute deadline within the 15-minute protocol maximum.
- Approval is amount limited, with the proxy as spender. Redemption burns through requestRedemption and requires no ERC20 allowance. Fresh account/chain checks surround simulation and signing; both chains' pause state blocks new frontend requests. Claim/refund paths do not depend on a fresh gold quote.
- Requests are asynchronous. Source receipt confirmation means a request exists, not that SGLD has arrived. Current states and accepted/rejected results are read on both chains. No result is invented from a transaction hash or an expired timer.
- A user can pay to dispatch/retry the persisted source request, then pay on Base to dispatch the committed settlement reply. Type3 receive options use 1,500,000 gas and no native drop. Live endpoint fees are reviewed before signing with 5% rounding-up headroom; excess is refunded by the endpoint. Each transaction still needs separate wallet confirmation and native gas. Network switching for settlement is explicit in the action label.
- After expiry, users can request cancellation, send that authenticated cancellation, and wait for a terminal Base result. Expiry alone never refunds USDG. Rejected mint refunds require a separate claim. Rejected redemptions restore SGLD through the authenticated result. Accepted redemptions expose FIFO processing and pull-claim controls. A zero claimable amount is never labelled paid; payment status requires a RedemptionPaid event. Log-provider failure renders an unknown payout status.
- Request IDs and pending transaction hashes are versioned, validated and stored per wallet/chain in localStorage. Each imported ID is revalidated against the actual onchain owner and recipient before actions. Lost browser state can be recovered by importing the request ID from the source IntentCreated event. Pending receipts retain their chain and replacement handling; a timeout does not unlock a duplicate submission. The UI polls at most five visible saved requests per page.

## Verification and remaining launch work

The scripts/verify-robinhood-read.ts command makes public read-only calls, validates actual configured identities/pricing and prints only public values. It sends no transaction and uses no wallet secret. Tests cover exact pricing/fee/cap math, Type3 options, ownership, stale/wrong-network reads and storage isolation, alongside existing Base tests.

This revision supplies user-driven request/reply dispatch and recovery, not an automatic funded relayer or a complete cross-chain indexer. Its local history does not promise discovery of all past activity. Existing Base points need an explicit escrow exclusion/Robinhood eligibility decision before cross-chain rewards are advertised. A bridge-transfer UI remains separate work. No actual wallet-signed Robinhood mint/redemption, real DVN-delivered packet, mobile handoff or live recovery acceptance has been performed by this revision. Independent security/storage review, issuer incident procedures, treasury replenishment and live round-trip acceptance remain launch work. Do not interpret successful reads or a passing build as completed financial acceptance.
